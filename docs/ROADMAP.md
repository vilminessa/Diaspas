# Diaspas — план развития

Порядок этапов отражает текущее состояние кода (ядро + webview + Tk-резерв,
несколько версий zapret, переключение стратегии). Каждый этап — отдельный
коммит; критерий готовности — pytest зелёный, pyflakes чист,
`tools/build_ui.py --check` актуален.

## Этап 0 — стабилизация (готово)

- Бандл UI пересобран из `ui_src` (был устарел: проверка актуальности падала,
  в exe ехал старый селектор без цели привязки).
- Переключение стратегии закоммичено: ядро (`core/presets.py`, `core/cmdparser.py`,
  layout win-bundle), мост API (`strategies`, `set_preset_strategy`,
  `apply_preset(key, strategy)`), Tk-резерв, селектор в окне.
- Регрессии закрыты тестами: `tests/test_strategy_overrides.py` — без найденной
  установки выбор терялся в том же вызове `set_strategy`; ошибка про чужую
  стратегию в win-bundle не объясняла, что там работают `preset*.cmd`.
- Живые прогоны вынесены в `tests/manual/` под порог `DIASPAS_LIVE=1`;
  smoke exe переехал в `tools/smoke_exe.py` и больше не привязан к пути одного
  компьютера.

## Этап 1 — стратегия как объект, а не имя файла

- **Каталог стратегий установки.** Для каждого `general*.bat` / `preset*.cmd`
  хранить: разобранные аргументы winws, источник (bat/cmd), хэш файла,
  применимость к версии zapret. UI показывает предпросмотр аргументов и
  отличие от текущей стратегии — сейчас пользователь видит «ALT7», но не то,
  что она делает.
- **«Попробовать без применения».** Кратковременный запуск winws с выбранной
  стратегией, пробы, автооткат к прежней. Ядро уже есть в A/B (`core/abtest.py`),
  поверх него — смена стратегии на N секунд.
- **Apply = транзакция.** Снимок → применить → пробы → при падении обхода
  откат к прежней стратегии и запись в журнал «до/после». Механизм отката есть
  для обновления версии (`ui/webapp.py:601`) — распространить на стратегию.
- Одна кнопка «пресет + стратегия», горячие клавиши, «сбросить к дефолту
  пресета» (в core уже есть через `set_strategy(key, None)`).
- **Экспорт/импорт связки** «пресет + стратегия + исключения доменов» в json:
  рабочую конфигурацию можно перенести между машинами.

Готовность: смена стратегии работает на обоих layout; неудачное применение
возвращает прежнюю стратегию автоматически; журнал содержит причину отката.

## Этап 2 — надёжность ядра

- **Очередь операций вместо флага.** Сейчас от защищённых только перебор
  (`_select_running`): `apply_preset`, `switch_version`, `update_latest`,
  `install_release` могут идти параллельно из разных потоков pywebview.
  Нужен один mutex + отмена (в том числе отмена скачивания zip).
- **Стабильный id установки.** Переопределения стратегий и кэш подбора
  привязаны к абсолютному пути (`settings.json`, `installs.json`,
  `strategy-cache.json`); перенос папки их теряет. Ввести `uid`, пути
  хранить как атрибут, добавить миграцию.
- **Схема и миграции `settings.json`.** Плоский `preset_strategies` →
  вложенный; повреждённый JSON → бэкап и восстановление вместо тихого
  «пустой словарь».
- **Единая точка `zapret_root`.** Присваивания разбросаны по четырём местам
  (`ui/webapp.py:422,567,781,839`); фоновый опрос может работать против старой
  папки. Один метод `set_install()` + событие в UI.
- **Тесты на непокрытое:** `core/probes.py`, вердикты `core/abtest.py`,
  `autoselect.summarize()` и возврат службы, парсинг `service.state()`,
  `webapp.strategies()/set_preset_strategy()/apply_preset(key, strategy)`,
  смена активной версии → другой список стратегий, запрос несуществующего
  файла стратегии.

Готовность: двойной клик по двум кнопкам не рвёт службу; переименование папки
не теряет настройки; core покрыт ≥70%, критичные пути apply/rollback — полностью.

## Этап 3 — диагностика и автоподбор

- **Расширяемые группы проб.** `core/probes.py:25` содержит 4 захардкоженные
  группы; добавить пользовательские цели (хост, порт, TCP/UDP, DNS, QUIC),
  историю замеров и сравнение «было/стало» по каждой цели.
- **Автоподбор:** выбор подмножества стратегий (сейчас перебираются все),
  критерий не только «ок», но и задержка, кэш результата с TTL и причиной,
  «повторить только проваленные». В UI честно показать, что на время перебора
  служба гасится (помощник запускает `.bat`/`.cmd` напрямую,
  `core/autoselect.py:151`).
- **«Диагноз одной кнопкой»:** пробы + A/B + журнал → вердикт (виноват zapret /
  блокирует DPI / нужен другой профиль / домен в исключения) и конкретная
  рекомендация.
- **Watchdog:** падение winws после старта → уведомление и один автоперезапуск
  с лимитом, вместо молчаливого «служба остановлена».

## Этап 4 — интерфейс, локализация, пресеты

- **i18n довести до конца:** `i18n.py` покрывает только Python-строки, весь
  текст окна зашит в `ui_src` на русском, часть ошибок в `ui/webapp.py` —
  литералы. Единый каталог для JS+Python, второй язык (en), тест полноты
  ключей, переключатель языка.
- **Редактор пресетов:** core читает `settings.presets`, но создать/изменить
  пресет в окне нельзя. Нужны CRUD, стратегия, Game Filter, IPSet, исключения
  и дописи доменов, валидация доменов, копирование пресета.
- **Трей + автозапуск с Windows** + быстрый переключатель пресетов/стратегий,
  «О программе».
- **Доступность:** обход с клавиатуры, aria, видимый фокус, масштаб 150%,
  узкое окно (сейчас минимум 940×640).

## Этап 5 — сборка, CI, релиз

- **`ci.yml` на push и pull request:** windows-latest, `build_ui.py --check`,
  pytest, pyflakes, сборка exe, `tools/smoke_exe.py`. Сейчас проверка есть
  только внутри `release.yml`/`beta.yml`, то есть «бандл устарел» всплывает
  в момент релиза.
- **`diaspas.spec`:** VERSIONINFO (версия из git tag), иконка, явные
  hidden-import для pywebview; в UI показывать версию Diaspas.
- **Самообновление Diaspas:** свой GitHub Release, проверка хэша, замена exe
  с перезапуском. Сейчас обновляется только zapret.
- **Подпись кода** (Trusted Signing/signtool) и SHA-256 в ассетах — снижает
  SmartScreen-шум для onefile-бинаря.
- **Ветко-процесс:** `dev` → PR в `main`, релиз только с `main`.

## Этап 6 — длинная перспектива

- **Абстракция «движок обхода»:** единый интерфейс (установка/старт/стоп/
  стратегии/пробы) для zapret и альтернатив. win-bundle уже второй backend —
  развитие существующего реестра layout, не новый слой.
- **Профили по активному приложению:** игра запускается → сама ставится нужная
  связка пресет+стратегия; история переключений в журнале.
- **Экспорт диагностического архива** (журнал + состояние + настройки) для
  баг-репортов; opt-in телеметрия отказов.
- **Документация:** скриншоты, CONTRIBUTING, разбор типичных сбоев.

## Риски, которые надо закладывать заранее

- Антивирус/WinDivert: `WinDivert64.sys` может блокироваться — нужен явный
  путь диагностики, а не «служба упала в 1067».
- Upstream zapret меняет имена файлов стратегий: каталог строится из
  установки, а не из списка в коде (вектор верный, довести до конца).
- Реестр/`schtasks` и UAC ведут себя по-разному на сборках Windows: сохранять
  резерв без задачи (одна повышенная сессия) и тестировать оба пути.
- WebView2 отсутствует → Tk-резерв обязан поддерживаться и покрываться
  тестами общих сценариев, иначе деградация молчит.
- Лицензия PolyForm Noncommercial ограничивает коммерческое распространение —
  влияет на способы дистрибуции и подписания.
