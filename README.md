# Diaspas (διάσπασις)

Менеджер обхода DPI для Windows: установка релизов
[zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube),
переключение пресетов стратегий и диагностика доступности
игровых и мессенджерных сервисов (Discord, YouTube, EA,
Ubisoft) одной кнопкой.

> **Diaspas не аффилирован с Flowseal, bol-van или WinDivert.**
> Это независимый инструмент. Сами компоненты обхода
> распространяются по своим лицензиям — см.
> [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Что делает

- **Скачивает релиз** zapret-discord-youtube с GitHub
  (последний релиз, с сохранением `LICENSE.txt`) —
  бинарники не входят в дистрибутив Diaspas.
- **Переключает пресеты**: одна кнопка выставляет стратегию
  `general (ALTn).bat`, режим Game Filter, режим IPSet и
  дописи в пользовательские списки доменов, затем
  переустанавливает службу.
- **Переключает стратегию**: вручную из списка всех
  `general*.bat` или автоматически — подбор по пробам
  (см. «Смена стратегии»).
- **Диагностирует**: TLS-пробы целевых хостов с учётом
  того, работает ли обход прямо сейчас.
- **A/B-тест**: кратковременно гасит службу и повторяет
  пробы — отделяет «ломает zapret» от «блокирует DPI».
- **Автоподбор стратегии**: перебирает все `general*.bat`
  в одной повышенной сессии и рекомендует рабочую.

## Смена стратегии

Стратегия — файл `general (ALTn).bat`, чьи аргументы становятся
`BinaryPathName` службы. Она отделена от пресета: пресет описывает
режимы (Game Filter, IPSet, списки доменов), а стратегию выбирает
отдельный переключатель в карточке «Состояние».

- **Вручную**: список всех `general*.bat` из папки zapret и
  кнопка «Применить». Меняется только служба — Game Filter, IPSet
  и пользовательские списки остаются как были. Выбранный файл
  сохраняется и используется всеми пресетами, пока его не изменят.
  Ручной выбор отключает авто-режим.
- **Авто**: подбор при запуске приложения (если служба работает)
  и после проб, которые показали сбой. Кандидаты идут в порядке
  ALT11, ALT12, затем остальные; перебор останавливается на первой
  полностью рабочей стратегии, победитель применяется сам. Пауза
  30 минут между подборками — блокировка выше обхода не должна
  вызывать бесконечные перезапуски службы.

Авто работает, пока Diaspas запущен: собственного демона или
задачи планировщика для фоновой смены стратегии нет. Пресет
«Выкл» авто не перебивает, а полный рейтинг всех стратегий
остаётся на вкладке «Диагностика».

## Версия и выпуск

Версия живёт в `version.py` — два значения с разными ролями:

- `__version__` — числовая (`X.Y.Z` или `X.Y.Z.N`): её читает
  `diaspas.spec` для `VersionInfo` exe (Свойства → Подробности) и тесты;
- `BUILD_LABEL` — полный тег сборки (`v0.1.2`, `b0.1.2`); пустая строка
  означает «собрано не из тега», и статус-бар показывает `unreleased`.

Коммитов с бампом версии не нужно: workflow `beta`/`release` перед
сборкой exe зовёт `tools/stamp_version.py <тег>` и вписывает оба
значения в одноразовое рабочее дерево CI — в git ничего не попадает.
Максимум четыре компонента версии: Windows `VersionInfo` больше не
принимает, поэтому «промежуточность» несёт префикс `b`, а не пятый разряд.

Где видно версию: статус-бар окна (`v0.1.2` или `b0.1.2 · бета`),
заголовок Tkinter-резерва, первая строка журнала («запуск интерфейса
(webview) — сборка b0.1.2») и `VersionInfo` exe. По подписи в журнале
можно определить, какая сборка делала пробы и перебор стратегий.

Выпуск (GitHub собирает и публикует сам, по тегу):

```bash
# бета: коммит в dev -> тег b* -> Pre-release, сборка из dev
git checkout dev && git push origin dev
git tag b0.1.2 && git push origin b0.1.2

# финал: main подтягивается до dev fast-forward -> тег v* -> релиз из main
git branch -f main dev && git push origin main
git tag v0.1.2 && git push origin v0.1.2
```

Гарды в конвейере: формат тега, «тег `b` обязан входить в `dev`», «тег
`v` — в `main`», публикация только на теге; `workflow_dispatch` без
тега проверяет конвейер, но ничего не выпускает (`unreleased`).
`tools/check_workflows.py` линтует сами workflow-файлы: пининг `uses:`
на SHA, `permissions`, триггеры, порядок джобов и **наличие шага
`stamp_version` перед сборкой** — иначе «версия берётся из тега»
остаётся обещанием, а exe выходит без версии.

Локальная сборка из тега — проставить версию перед PyInstaller:

```bash
python tools/stamp_version.py v0.1.2
python -m PyInstaller diaspas.spec
```

## Пресеты по умолчанию

Стратегия в таблице — значение по умолчанию: если выбрано
что-то другое, пресет ставит выбранный файл.

| Пресет | Стратегия | Game Filter | IPSet | Списки |
|---|---|---|---|---|
| Discord / YouTube | ALT11 | — | — | — |
| Apex / EA | ALT11 | all | any | `ea.com` в исключения |
| Ubisoft | ALT11 | all | any | `ubisoft.com`, `ubi.com` в исключения |
| The Finals | ALT11 | all | any | `embark.io` в исключения домена и `34.49.47.233/32` в `ipset-exclude-user.txt` |
| Максимум для игр | ALT11 | all | any | — |
| Выкл | — | — | — | — |

Правила игрового фильтра (`--filter-tcp=%GameFilterTCP%`,
`--filter-udp=%GameFilterUDP%`) не читают `--hostlist-exclude`, поэтому
для защиты бэкенда игры от десинка нужен IP: доменное исключение в них
не работает. CIDR пишется в `ipset-exclude-user.txt` один раз и не затирает
чужие строки.

## Управление правами

Операции со службой выполняются через служебную задачу
Windows с уровнем Highest: единственный запрос UAC при
регистрации задачи, дальше Diaspas запускает её через
`schtasks /Run` без диалогов. Всего две задачи:
`DiaspasService` (служба) и `DiaspasSelector` (перебор
стратегий).

Состояние службы читается **без прав** (`sc query` +
реестр) — обычная проверка карточки не дёргает UAC.

## Журнал

Все события пишутся в `%LOCALAPPDATA%\Diaspas\diaspas.log`
(UTF-8 с BOM, ротация при 512 КБ). Окно показывает то же
плюс хвост прошлого запуска — закрытое окно больше не
теряет диагностику.

## Запуск из исходников

```
python main.py           # webview (pywebview/EdgeChromium)
python main.py --debug   # webview с DevTools — видна консоль JS
python main.py --tk      # Tkinter-резерв, без попытки webview
```

Зависимости — только стандартная библиотека
(Tkinter, urllib, ctypes). Тесты:

```
pip install pytest
python -m pytest tests/
```

Ручные прогоны (нужна сеть, часть — UAC):

```
python tests/run_probes.py        # пробы всех групп
python tests/run_ab.py ubisoft    # A/B-тест по группе
python tests/run_select.py        # автоподбор (подмножество)
python tests/run_strategy.py --list                # список стратегий
python tests/run_strategy.py "general (ALT7).bat"  # ручная смена стратегии
python tests/run_strategy.py --auto                # автоцикл: пробы + подбор
python tests/run_ubisoft_fix.py   # применить пресет end-to-end
```

### Разработка: debug.bat

`debug.bat` — консоль управления проектом. Без аргументов открывает меню
(с контекстом: ветка, незакоммиченные файлы, версия и подпись сборки,
папка zapret, состояние службы, стратегия, режим и автопауза), с номером
пункта — сразу выполняет его:

```
debug.bat              # меню
debug.bat 5            # тесты офлайн
debug.bat 6            # линт и синтаксис (compileall, pyflakes, node, бандл, workflows)
debug.bat 7            # пересобрать бандл UI
debug.bat 8            # CI-шаги локально: бандл -> pytest -> pyflakes -> workflows
debug.bat 9            # состояние службы и установки (без прав)
debug.bat Q            # файлы, на которые ссылается BinaryPathName (ошибка 1067)
debug.bat A            # список стратегий и активная
debug.bat B "general (ALT7).bat"   # сменить стратегию вручную (UAC)
debug.bat C            # автоцикл: пробы + подбор + применение (UAC)
debug.bat F ea         # A/B-тест группы (discord|youtube|ea|ubisoft|finals)
debug.bat G            # служебные задачи UAC
debug.bat I --yes      # переустановка релиза без вопроса
debug.bat J            # собрать exe + smoke-прогон
debug.bat V            # версия и подпись сборки (как в статус-баре)
debug.bat U v0.1.2     # вписать версию из тега перед сборкой
debug.bat K / L        # git статус / add+commit+push
debug.bat O            # копия профиля в backup/<timestamp>
debug.bat P --yes      # закрыть процессы Diaspas (winws не трогает)
```

Пункты с перезапуском службы, UAC, `git push`, удалением задач и
переустановкой релиза в меню спрашивают подтверждение; в быстром режиме
требуют `--yes` и иначе отказываются. Быстрый режим передаётся аргументом
(`--scripted`), а не переменной окружения: env наследуется дочерним
процессам, и pytest под пунктом CI принял бы чужой режим.

Сам `.bat` — ASCII и без спецсимволов cmd: cmd перечитывает батч по
байтовому offset после `chcp 65001`, кириллица сдвигает offset и выполняет
фрагменты строк. Весь текст и логика консоли — в `tools/debug_ctl.py`.

## Сборка

```
pip install -r requirements.txt
pyinstaller diaspas.spec
```

Готовый `dist/Diaspas.exe` — onefile, ~12,5 МБ; `VersionInfo` берётся из
`version.py` (для сборки из тега сначала `python tools/stamp_version.py
v0.1.2`). Релизы и беты GitHub собирает сам по тегу — см. «Версия и
выпуск».

## Статус

Реализовано: установка релизов с GitHub, пресеты,
управление службой (один UAC), пробы Discord/YouTube/EA/
Ubisoft/The Finals, A/B-диагностика, перебор стратегий, ручная и
автоматическая смена стратегии, версионирование и полосы
выпуска (beta/release, SLSA-провенанс), консоль проекта
`debug.bat`, GUI.

Проверено на живой системе: A/B достоверно разводит
«ломает zapret» / «блокирует DPI»; пресет «Ubisoft»
чинит `account.ubisoft.com` (было 2/3 → стало 3/3);
автоподбор на этой машине закрыл цели ALT4 (11/11), а
ALT11 и ALT12 — нет, и обход переключился на ALT4 сам.

The Finals: web-домены игры припаркованы (`thefinals.com` —
лендер «for sale» на GoDaddy/AWS, `finals.game` — Gandi), а
зона `thefinals.com` имеет wildcard, поэтому `api.`/`cdn.`/
`status.` резолвятся, но TLS отвечает «unrecognized name» —
это мёртвый хост, а не DPI (A/B: одинаково с обходом и без).
Живой бэкенд — платформа Embark: `api.embark.io` (GCP),
`events.embark.io` (Vercel), `embark.io` (Firebase); все три
отвечают и без обхода, поэтому входят в исключения пресета
«The Finals». UDP-серверы матча с этого ПК не видны — их
нужно замерять на игровом ПК (`netstat`/`Get-NetUDPConnection`).
